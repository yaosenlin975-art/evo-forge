## 🎭 双视角审查

### 🧬 专家视角：知识整合质量

| 维度 | 关注 | 专家问的问题 |
|------|------|-------------|
| 知识准确性 | 信息对吗？ | 有来源吗？能验证吗？ |
| 知识完整性 | 缺什么？ | 关键点都覆盖了吗？ |
| 知识关联性 | 能串起来吗？ | 新知识能定位到现有框架吗？ |
| 知识可用性 | 能用吗？ | 下次遇到问题能直接查出来吗？ |

### 😈 找茬视角：知识有效性

| 问题 | 用户会问 | 找茬点 |
|------|---------|--------|
| 知识过时 | "这信息还有效吗？" | 知识还在用，但源头已经变了 |
| 知识孤岛 | "我之前记过这个吗？" | 多个地方记了同一件事，互不关联 |
| 知识噪音 | "记了那么多，有用的几条？" | 90%是垃圾，10%是黄金，但分不清 |
| 知识断层 | "上次分析的结果呢？" | 分析完了，结论不知道去哪了 |


## 📚 知识库优化 v3.0 ⭐新增

### 核心概念

与plans-driver的knowledge_base形成联动，确保学习资料的质量：

```
知识库质量 → 学习效率 → 用户掌握程度
     ↑
 Darwin优化
```

### 质量标准（7项检查）

| # | 检查项 | 要求 | 字数/数量 |
|---|--------|------|-----------|
| 1 | **原理说明** | 技术本质+背景+为什么需要 | ≥200字 |
| 2 | **关键要点** | 至少5个要点 | ≥5个 |
| 3 | **对比分析** | 与同类技术对比+优缺点 | 有表格 |
| 4 | **代码示例** | 完整可运行+注释 | ≥1个 |
| 5 | **面试真题** | 高频题+详细答案 | ≥2题 |
| 6 | **横向拓展** | 同级知识点+关系说明 | ≥2个 |
| 7 | **纵向拓展** | 前置+进阶方向 | 有 |

### 优化流程

```
Step 1: 扫描知识库
├── 查找 plans/*/knowledge_base.md
├── 解析章节结构
└── 建立技术点清单 [1.1, 1.2, ...]

Step 2: 逐项评估
├── 原理完整性 → 打分
├── 对比分析 → 检查表格
├── 代码示例 → 检查可运行
├── 面试真题 → 检查数量
└── 拓展内容 → 检查完整性

Step 3: 识别缺失
├── 缺失项记录
├── 计算完整度百分比
└── 按缺失程度排序

Step 4: 生成优化方案
├── 补充原理说明
├── 添加对比表格
├── 补充代码示例
└── 完善面试题

Step 5: 执行优化
├── 生成完整内容
├── 替换/追加到knowledge_base.md
└── 记录优化结果
```

## 工作流程（通用）

```
用户输入 → 目标识别 → 智能扫描 → 方案生成 → 执行优化 → 验证报告
```

### 步骤 1：目标识别

```python
def identify_type(user_input):
    if "配置" in user_input:
        return "config"
    elif "文档" in user_input:
        return "doc"
    elif "结构" in user_input or "目录" in user_input:
        return "structure"
    elif "数据" in user_input:
        return "data"
    elif "docker" in user_input.lower() or "容器" in user_input:
        return "container"
    elif "ci" in user_input.lower() or "workflow" in user_input.lower():
        return "pipeline"
    elif "全局" in user_input or "健康" in user_input or "诊断" in user_input:
        return "global"
    else:
        return "generic"
```

### 步骤 2：智能扫描

```python
strategies = {
    "memory": scan_memory_dreaming,      # 🌙
    "config": scan_config_files,
    "doc": scan_documentation,

    "data": scan_data_files,
    "container": scan_container_config,
    "pipeline": scan_ci_cd,
    "global": scan_workspace_health,
    "generic": scan_generic,
}
```

### 步骤 3：方案生成

```python
evolution_plan = {
    "problem": "当前问题描述",

    "actions": [
        {"file": "文件路径", "change": "具体修改", "confidence": 0.9},
    ],

```

### 步骤 4：执行优化

| 置信度 | 行为 |
|--------|------|
| ≥ 0.9 | 直接执行 |
| 0.7-0.9 | 执行，可回滚 |
| 0.5-0.7 | 先确认再执行 |
| < 0.5 | 只提建议 |

### 步骤 5：验证报告

#### 5.1 语句精简验证
对进化报告进行精简，确保用户能快速抓住重点：

| 原则 | 说明 |
|------|------|
| 精炼摘要 | 报告开头的概览控制在 5 条以内要点 |
| 表格优先 | 对比/评分类信息用表格而非段落描述 |
| 删冗余分析 | 同一论点多角度重复只保留最有力的一个 |
| 结论前置 | 每条分析先说结论，再说依据 |
| 保持完整性 | 精简不删关键数据、路径、评分 |

#### 5.2 检查清单

### 通用评分维度

| 维度 | 权重 | 检查点 |
|------|------|--------|
| **完整性** | 20% | 无关键信息缺失、无死链 |
| **一致性** | 20% | 内部逻辑自洽、无矛盾 |

| **效率** | 20% | 无冗余、无重复 |
