> **EvoForge 子技能** | 版本: v1.5.0 | 父技能: evo-forge | 默认直接执行 ⚡

## 职责

优化 Skill 的 SKILL.md 文件，确保结构规范、触发词完整、执行流程清晰。

> 📡 **[来自: expert-brainstorm] 新增拆分职责**
> 
> 若发现技能功能过多、主体过大，应考虑拆分成子技能，并改造为调度器。

> 🔗 **[来自: evo-forge子技能联动规则] 新增子技能检查职责**
>
> 优化一个技能时，自动检查该技能是否有子技能，如有则提示用户是否一起优化。

## 优化流程

### Phase 0: 理解

1. 读取目标 SKILL.md 完整内容
2. 识别 Phase/检查点/示例/核心概念数量
3. **检查子技能**（🔗子技能联动规则1）：
   - 检查`skills/xxx/`目录下是否有`sub_skills/`子目录
   - 检查SKILL.md的frontmatter是否有`sub_skills`字段
   - 检查是否有`xxx-yyy/SKILL.md`格式的子技能文件
4. 如有子技能，提示用户：
   ```
   ---
   发现目标技能有N个子技能：
   1. xxx-search
   2. xxx-fetch
   
   是否一起优化？
   
   回复"全部优化"、"只优化主技能"或"选择优化 [子技能名]"。
   ---
   ```
5. **依赖预扫描**（🔗Phase 0.7前置）：
   - 扫描SKILL.md中所有命令/工具/路径/环境变量引用
   - 识别所有潜在依赖项，建立依赖清单
6. 输出理解摘要（含依赖预扫结果）

### Phase 0.7: 依赖分析（新增）

> 🩹 **[来自: skill-healer] 新增依赖管理**
>
> 优化技能时，检查该技能是否依赖外部工具/环境，若有依赖则检查是否会自动安装/修复，不会自动处理则添加自动安装/修复逻辑。

**依赖检测范围**：

| 依赖类型 | 检测模式 | 示例 |
|----------|----------|------|
| **外部命令** | `python3 `、`bash `、`shell`、执行脚本 | `python3 xxx.py` |
| **系统工具** | `ffmpeg`、`docker`、`curl`、`wget` | ffmpeg视频处理 |
| **Python包** | `import`、`pip install`、`requirements` | `import requests` |
| **Node包** | `require(`、`npm install`、`node_modules` | `require('axios')` |
| **文件路径** | 硬编码绝对路径（`/app/...`） | 图片/模型路径 |
| **环境变量** | `os.getenv`、`process.env` | API密钥读取 |
| **其他Agent** | `chat_with_agent`、`delegate_external_agent` | 调用其他Agent |
| **其他Skill** | 引用外部SKILL.md、调用`skill-manager` | 依赖skill-installer |
| **IMAP/SMTP** | himalaya邮件工具 | 发送邮件功能 |
| **Docker** | docker-manager、Docker容器 | 容器管理功能 |

**依赖自愈检测流程**：

```
扫描SKILL.md所有内容
    ↓
识别所有依赖项（命令/工具/包/路径/环境变量/Agent/Skill等）
    ↓
┌─────────────────────────────────────┐
│ 检查依赖是否被自动处理               │
│                                     │
│ ✅ 自动处理（通过，跳过）            │
│   • 使用铁律5规则自动安装的工具      │
│   • 调用了skill-manager自动修复     │
│   • 调用了docker-manager自动部署    │
│   • 调用了skill-healer自愈          │
│   • 使用config-editor自动处理配置   │
│                                     │
│ ❌ 未自动处理（标记待修复）          │
│   • 硬编码命令但没有安装逻辑        │
│   • 依赖环境但没有检查+安装逻辑      │
│   • 引用其他Agent但无可用性检查      │
│   • 引用其他Skill但无安装/调度逻辑  │
└─────────────────────────────────────┘
    ↓
为每个❌项生成修复方案
```

**自愈方案生成**：

| 依赖类型 | 自愈方案 |
|----------|----------|
| 外部命令缺失 | 任务前加`which xxx`检查，未找到则调用`execute_shell_command`安装 |
| Python包缺失 | 任务前加`python3 -c "import xxx"`检查，失败则`pip install` |
| Node包缺失 | 任务前加`node -e "require('xxx')"`检查，失败则`npm install` |
| 文件路径失效 | 任务前检查文件是否存在，不存在则创建目录/下载 |
| 环境变量缺失 | 任务前检查`os.getenv('xxx')`，缺失则用默认值或报错提示 |
| Agent不可用 | 调用`list_agents`检查Agent存在，不存在则跳过或用fallback |
| Skill不可用 | 调用`chat_with_agent(to_agent="skill-manager", text="检查xxx是否安装")` |
| Docker容器停 | 调用`docker-manager`重启容器，或在执行前检查状态 |
| 邮件工具缺失 | 调用`himalaya`前检查`which himalaya`，未找到则提示用户安装 |

**自愈注入模板**（插入到Phase 2优化）：

```markdown
### 依赖自愈检查（任务前执行）

| 依赖项 | 检查方式 | 自动修复方式 |

| ffmpeg | `which ffmpeg` | `apt-get install -y ffmpeg` 或 `brew install ffmpeg` |
| himalaya | `which himalaya` | 提示用户安装或使用Python邮件库替代 |
```

### Phase 3: 验证

#### 3.1 语句精简验证

| 原则 | 说明 | 示例 |

所有优化报告和日志必须写入被优化技能目录下的 `evo-forge/` 文件夹：

## ⚠️ Fallback处理

| 场景 | 处理 |
|------|------|
| 目标文件不存在 | 提示文件路径错误，终止优化 |
| 网络不通（调研时） | 跳过Phase 3.5，用本地知识库 |
| 工具缺失（拆分时） | 提示安装依赖，或跳过拆分 |
| 优化后完整性<80% | 回滚到优化前版本 |
| 依赖自愈注入失败 | 保留原始依赖描述+标记，待后续手动处理 |
| 依赖检查语法错误 | 回滚该依赖的修复，继续其他优化 |
| 注入位置冲突 | 改用SKILL.md末尾依赖章节集中管理 |
